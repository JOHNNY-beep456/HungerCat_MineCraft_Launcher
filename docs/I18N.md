# 语言系统（i18n）规范

轻量自研 i18n，不引入第三方库。词典全部是 **JSON 分片**，按语言分目录存放；
`i18n/index.ts` 只负责组装，且**语言清单与分片全部自动发现**（`import.meta.glob`），
增删文案 / 新增语言都不需要改任何代码。

## 一、目录结构

```
src/renderer/src/i18n/
├── index.ts                    组装：自动发现各分片 → 合并成字典 → createTranslator
├── types.ts                    基础类型（Locale / LocaleDict / TFunction / FALLBACK）
└── locales/
    ├── zh-CN/meta.json         该语言的显示名与排序（label / order）
    ├── zh-CN/<板块>.json        源语言，也是兜底语言
    ├── zh-TW/{meta.json,<板块>.json}
    └── en/{meta.json,<板块>.json}
```

- `index.ts` 用 `import.meta.glob('./locales/*/meta.json')` 得到语言清单、
  `import.meta.glob('./locales/*/*.json')` 得到全部词典分片；`meta.json` 之外的文件
  都当作词典分片。**没有语言名 / 分片名的硬编码**。
- `LOCALES`（设置页语言选项）由 `meta.json` 生成，新增语言目录即自动出现。

三种语言各 11 个分片，共 33 个词典 JSON，当前合计 **1202 条**文案（每种语言）。

## 三、键命名规范

- 用**点号分层**，形如 `板块.区域.语义`，例如 `settings.java.manual.title`。
- 键名必须与所在分片的**前缀一致**（`shell.*` 只出现在 `shell.json`），便于定位。
- 语义要具体：`xxx.title` / `xxx.subtitle` / `xxx.desc` / `xxx.confirm` / `xxx.cancel`。
- 同一分片内的键不重复；分片之间前缀不重叠，因此合并顺序不影响结果。

## 四、占位符

文案里的变量用花括号，调用时通过第二参数传入：

```json
{ "shell.update.title": "发现新版本 v{n}" }
```

```ts
t('shell.update.title', { n: '0.6.8' })   // → 发现新版本 v0.6.8
```

替换是**纯字符串替换**（`s.split('{k}').join(v)`），不做转义，也不支持嵌套。

## 五、兜底链

```
目标语言 → 简体中文（zh-CN） → 原样返回键名
```

最后一步返回键名是**故意的**：界面上出现 `settings.xxx.yyy` 这样的裸键，就说明漏翻了，
一眼能看出来。新增语言时只需新建 `locales/<语言 id>/` 目录并放入 `meta.json` + 分片
JSON，**无需改动任何代码**（`Locale` 已是普通 `string`，`LOCALES` 自动生成）。
详见 [SETTINGS.md](./SETTINGS.md) 第四节。

## 六、代码用法

```ts
import { createTranslator, LOCALES, isLocale } from './i18n'

const t = createTranslator('zh-CN')
t('nav.home')                       // 启动游戏

// 组件里统一从全局状态取（会随语言设置自动更新）
const { t, locale } = useApp()
```

## 七、新增 / 修改文案的流程

1. 在**对应板块**的 `locales/zh-CN/<板块>.json` 里加键（源语言先行）。
2. **同步补上** `zh-TW/` 与 `en/` 的同名键 —— 三种语言的键集合必须**完全一致**。
3. 代码里用 `t('<完整键名>')` 引用。
4. 跑 `npm run typecheck`（JSON 导入类型受 tsconfig 的 `resolveJsonModule` 约束）。

### 一致性自检

三语键集合若不一致，界面会出现「某个语言少一条」的隐蔽问题。可在仓库根跑一段脚本比对，
思路：对每个分片，取三份 JSON 的键集合做差集，非空即报错。改文案后建议顺手核对一次。

## 八、注意事项

- **不要**把文案写死在组件里；即使只有中文，也走 `t()`，否则将来无法翻译。
- 文案里的**换行**在渲染时按需处理：更新日志等 Markdown 场景由 `marked` 的 `breaks` 选项
  把单个换行转成 `<br>`；普通文本用 CSS `white-space: pre-line`。
- 键名一旦发布就不要再改（等同破坏性变更）；改文案只改值，不改键。
